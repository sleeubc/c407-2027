R code runs in two places

Console

Quick commands, checks, and package installation. Nothing is saved.

Quarto document

Code, results, and your notes in one .qmd file. This is the record of your analysis.

Experiment in the Console. Keep everything you want to reproduce in the Quarto document.

Use the Console for quick commands

Type and run this command in Positron’s Console:

mean(mtcars$mpg)
[1] 20.09062

The result appears directly below the command, and it is gone when you restart R.

Quick check: where does the code go?

A. Console B. Quarto document

  1. install.packages("tidyverse")
  2. The code that produces the figures for your presentation
  3. ?mean, to read a help page once

Answers: 1. A (setup, not analysis). 2. B (it must be reproducible). 3. A (a one-time lookup).


```{r}
#| label: data
bca <- read_rds("data/bca262.rds")
avg_price <- bca |>
  group_by(sale_year = year(sale_date)) |>
  summarise(avg_price = mean(price, na.rm = TRUE))
```
```{r}
#| label: plot
avg_price_plot <- ggplot(avg_price, aes(sale_year, avg_price)) +
  geom_line() +
  geom_point() +
  scale_y_continuous(labels = scales::label_dollar()) +
  labs(x = NULL, y = "Average sale price",
       caption = "2026: January to early March only")
avg_price_plot
```

Render a report

Running and rendering are different

Running

Uses your current R session. Objects you made in the Console are still there.

Rendering

Starts a fresh R session, runs every chunk from top to bottom, and makes a document for readers.

“It works when I run it but fails when I render” usually means the document uses something you created only in the Console.

Render your document

  • Click Preview in Positron,
  • press Ctrl/Command + Shift + K, or
  • run this in the Terminal:
quarto render scripts/sample_analysis.qmd

The result is scripts/sample_analysis.html: your title, code, and chart.

Render often. A document that renders from scratch is reproducible.

Markdown formats your text

Your document’s text uses Markdown:

You type The report shows
## Average sale prices by year a section heading
**rose for two decades** rose for two decades
*nominal* nominal
- Prices are … a bullet point
[BC Assessment](https://www.bcassessment.ca) BC Assessment

Leave a blank line before every heading and list, as in your document. Without it, Quarto prints the ## or - as plain text.

The parts of a Quarto document

A Quarto document has four parts

---
title: "Home prices in Metro Vancouver"
format: html
---

```{r}
#| label: setup
library(tidyverse)
```

## Average sale prices by year
  • YAML header (between the --- lines): the title and output format.
  • Code chunk (starts with ```{r}): R code.
  • Chunk options (lines starting with #|): a label, or echo: false to hide code.
  • Markdown text: everything else.

Hide code from readers

Chunk option Code Output
(default) shown shown
echo: false hidden shown
include: false hidden hidden, but the chunk still runs

To hide the code of every chunk, add this to your YAML header and render again:

execute:
  echo: false

Hiding code changes only the output. The code stays in your .qmd, which is what you submit and defend.

Exercise: hide the startup messages

Your document still starts with the tidyverse startup messages.

  1. Which chunk option hides them? Add it to your setup chunk.
  2. Render again.

Answer: #| include: false in the setup chunk. It hides the chunk’s code and output, but the chunk still runs, so later chunks can use the tidyverse. message: false in the YAML does not hide these messages.

Typst turns your document into a PDF

Change format: html to format: typst, and render again: the result is scripts/sample_analysis.pdf. Typst comes with Quarto, so you do not need LaTeX, which format: pdf requires.

To make both a PDF and a web page, list both formats:

format:
  typst: default
  html: default
  • Indent typst and html under format:, by the same amount.
  • Use spaces, not tabs.
  • Preview shows the first format listed.

A PDF is static: use static maps (tmap_mode("plot")) and simple, narrow tables.

Paths

The working directory is R’s starting point

Your data chunk reads "data/bca262.rds". R looks for it from the working directory, the folder R uses when it reads or writes a file:

getwd()
[1] "/Users/you/c407"

When you open the c407 folder in Positron, it becomes the working directory.

  • Positron workspaces: https://positron.posit.co/migrate-rstudio-rproj.html

R looks only in the working directory

Run this in the Console:

bca <- read_rds("bca262.rds")
Error in `readRDS()`:
! cannot open the connection

It fails because the file is inside the data folder, not directly in c407.

Experiment in the Console, not in the document: an error in a chunk stops the render.

A relative path starts from c407

Your data chunk names the folder too:

bca <- read_rds("data/bca262.rds")

c407 → data → bca262.rds

Paths start from c407, not from scripts

Your .qmd file is in scripts/, yet the render found data/bca262.rds. _quarto.yml tells Quarto to run code from the c407 folder:

project:
  execute-dir: project

In every document, paths start from c407, whether you run a chunk or render the whole file.

Relative paths keep working when the folder moves

  • Use / between folders: data/bca262.rds.
  • Relative paths are shorter than full paths such as /Users/you/Downloads/c407/data/bca262.rds.
  • They keep working when the whole c407 folder moves to another place or computer.

Never use setwd() or full paths in course documents.

Save a figure to use outside Quarto

Your PDF already includes the chart. For PowerPoint or Google Slides, write it to a file with a relative path:

ggsave("temp/avg_price.png", avg_price_plot, width = 8, height = 4.5)

c407 → temp → avg_price.png

  • Add the chunk below your plot chunk, run it, and find avg_price.png in the Explorer.
  • Every render saves the PNG again, so it always matches your code.
  • width and height are in inches; 8 × 4.5 fits a 16:9 slide.

Save figures with ggsave(), never with a screenshot.
