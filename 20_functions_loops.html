Lists, functions, and loops

COMM 407 · Reading the code AI writes

Sanghoon Lee

31 October 2026

AI code uses three things we have not covered

  • Lists hold results of different types and sizes.
  • Functions package steps so they can be repeated.
  • Loops repeat a step for each year, city, file, or street.

AI writes these easily. You need to read them:

  • In your code defence, you explain code like this line by line.
  • In exams, you predict what it returns and find its bugs.

Today’s goal is reading, not writing: explain every line of a function or loop that AI gives you.

Packages and data

bca <- read_rds("data/bca262.rds")                 # deck 03
pumf <- read_rds("data/2021_census_pumf_ind.rds")  # deck 11

A list holds items of any type and length

listing <- list(address = "2561 Western Ave",
                price = 274900,
                past_prices = c(180000, 215000))
str(listing)
List of 3
 $ address    : chr "2561 Western Ave"
 $ price      : num 274900
 $ past_prices: num [1:2] 180000 215000
  • A vector holds values of one type (deck 03).
  • A list can hold anything: numbers, text, tibbles, even other lists.

[ ] keeps the list; [[ ]] takes the item out

listing["price"]      # a list with one item
$price
[1] 274900
listing[["price"]]    # the number itself
[1] 274900
listing["price"] * 2  # you cannot multiply a list
Error in `listing["price"] * 2`:
! non-numeric argument to binary operator

listing$price is a shortcut for listing[["price"]].

Think of a train. [ ] gives you a shorter train; [[ ]] gives you what is inside one car.

A tibble is a list of columns

tb <- tibble(price = c(5e5, 7.5e5, 1.2e6),
             city = c("Burnaby", "Surrey", "Vancouver"))
is.list(tb)
[1] TRUE
length(tb)
[1] 2
tb[["city"]]
[1] "Burnaby"   "Surrey"    "Vancouver"

length() of a tibble counts columns, not rows. Use nrow() to count rows.

condo <- bca |>

fit <- feols(log(price) ~ log(floorarea), data = condo)

The example presentations use coef(m)[["westTRUE"]] and summary(fit)$coefficients[2, 4], which students can now read.

A function turns inputs into an output

pct_change <- function(new, old) {
  100 * (new - old) / old
}
pct_change(new = 1500000, old = 1200000)
[1] 25
  • new and old are the arguments: the inputs.
  • The code between { } is the body.
  • The function returns the value of the last line in the body.

Arguments match by name, then by position

pct_change(new = 1500000, old = 1200000)
[1] 25
pct_change(old = 1200000, new = 1500000)
[1] 25
pct_change(1200000, 1500000)
[1] -20

Without names, R matches arguments by position. Values in the wrong order run without an error and give a different answer.

A default is a choice you may not see

mean_price <- function(data, type = "S/F Res") {
  data |>
    filter(act_use_cat == type) |>
    summarise(avg = mean(price, na.rm = TRUE), sales = n())
}
mean_price(bca)
# A tibble: 1 × 2
       avg  sales
     <dbl>  <int>
1 1002106. 521229
  • mean_price(bca) looks like the average of all sales, but the default type = "S/F Res" leaves out every strata unit.
  • Built-in functions have defaults too: mean() has na.rm = FALSE, so one missing price makes the average NA. Type ?mean to see them.

Names in the body come from the arguments, or from outside

cutoff <- 1000000
n_above <- function(data) sum(data$price > cutoff, na.rm = TRUE)
n_above(bca)
[1] 234174
cutoff <- 2000000
n_above(bca)
[1] 55774

cutoff is not an argument, so R looks for it outside the function. The same call gives a different answer after cutoff changes. In Quarto, the result depends on which chunks ran first.

return() can end a function early

price_label <- function(p) {
  if (is.na(p)) return("unknown")
  if (p >= 1000000) "$1M or more" else "under $1M"
}
price_label(1500000)
[1] "$1M or more"
price_label(NA)
[1] "unknown"
  • if (condition) A else B runs A when the condition is TRUE, and B otherwise.
  • return() stops the function and returns its value right away.

if () takes one TRUE or FALSE; if_else() takes a column

prices <- c(800000, 1500000)
price_label(prices)
Error in `if (is.na(p)) ...`:
! the condition has length > 1
if_else(prices >= 1000000, "$1M or more", "under $1M")
[1] "under $1M"   "$1M or more"

Inside mutate(), use if_else() or case_when(). Use if for a single choice, such as whether a file exists.

\(x) is a short way to write a function

function(x) x / 1000
\(x) x / 1000        # the same function
~ .x / 1000          # older purrr style; also the same

A function written in place has no name. You have seen this before:

pumf |> map_chr(\(col) class(col)[1])           # deck 11
scale_y_continuous(labels = \(x) paste0(x, "%"))  # a chart axis

A for loop repeats code for each item

for (yr in 2023:2025) {
  n <- sum(year(bca$sale_date) == yr)
  print(paste(yr, n))
}
[1] "2023 45033"
[1] "2024 44695"
[1] "2025 44419"
  • yr takes each value in turn: 2023, then 2024, then 2025.
  • The body runs once for each value.

A loop must save each result somewhere

for (yr in 2023:2025) {
  result <- bca |>
    filter(year(sale_date) == yr) |>
    summarise(sale_year = yr, avg = mean(price, na.rm = TRUE))
}
result
# A tibble: 1 × 2
  sale_year      avg
      <int>    <dbl>
1      2025 1090192.

Each pass overwrites result, so only 2025 is left. The code runs, and the number looks reasonable.

Save each result in a list, then stack them

results <- list()
for (yr in 2023:2025) {
  results[[as.character(yr)]] <- bca |>
    filter(year(sale_date) == yr) |>
    summarise(avg = mean(price, na.rm = TRUE))
}
bind_rows(results, .id = "sale_year")
# A tibble: 3 × 2
  sale_year      avg
  <chr>        <dbl>
1 2023      1129297.
2 2024      1151162.
3 2025      1090192.

results[["2023"]] <- … adds an item named “2023”. bind_rows() stacks the tibbles, and .id keeps the names as a column.

Many loops are group_by() in disguise

bca |>
  filter(year(sale_date) %in% 2023:2025) |>
  group_by(sale_year = year(sale_date)) |>
  summarise(avg = mean(price, na.rm = TRUE))
# A tibble: 3 × 2
  sale_year      avg
      <dbl>    <dbl>
1      2023 1129297.
2      2024 1151162.
3      2025 1090192.
  • Same numbers, and no result to overwrite.
  • A loop over groups in one table can usually be a group_by(). Ask the AI for that version.
  • Loops are the right tool when each item needs its own input: a file, an API call, a street.

map() is a loop that returns a list

avg_in_year <- function(yr) {
  bca |>
    filter(year(sale_date) == yr) |>
    summarise(sale_year = yr, avg = mean(price, na.rm = TRUE))
}
map(2023:2025, avg_in_year) |> list_rbind()
# A tibble: 3 × 2
  sale_year      avg
      <int>    <dbl>
1      2023 1129297.
2      2024 1151162.
3      2025 1090192.
map(2023:2025, avg_in_year)  # is the same as
list(avg_in_year(2023), avg_in_year(2024), avg_in_year(2025))

list_rbind() stacks the list of tibbles, like bind_rows().

map_dbl() and map_chr() return a vector

median_in_year <- \(yr) median(bca$price[year(bca$sale_date) == yr],
                               na.rm = TRUE)
map_dbl(2023:2025, median_in_year)
[1] 857000 870900 830000

A tibble is a list of columns, so map() over a tibble visits each column. Now you can read this line from deck 11:

pumf |> map_chr(\(col) class(col)[1]) |> table()

 factor numeric 
    105      39

Older code uses lapply(), which works like map(), and sapply(), which guesses whether to return a vector or a list.

Results can disappear without a warning

avg_2025 <- function(city) {
  d <- bca |> filter(juris_label == city, year(sale_date) == 2025)
  if (nrow(d) < 30) return(NULL)   # too few sales to average
  summarise(d, avg = mean(price, na.rm = TRUE), sales = n())
}
cities <- c("City of Vancouver", "University Endowment Lands",
            "City of Burnaby")
map(set_names(cities), avg_2025) |> list_rbind(names_to = "city")
# A tibble: 2 × 3
  city                   avg sales
  <chr>                <dbl> <int>
1 City of Vancouver 1427877.  7666
2 City of Burnaby   1025556.  4429

set_names() names each result after its city, and names_to makes the names a column.

Three cities in, two rows out. The UEL had 12 sales in 2025, so avg_2025() returned NULL, and list_rbind() dropped it without a warning.

Read across() as “for each of these columns”

codes <- c(88888888, 99999999)
pumf |>
  filter(CMA == "Vancouver") |>
  mutate(across(c(TotInc, Wages), \(x) if_else(x %in% codes, NA, x))) |>
  summarise(across(c(TotInc, Wages),
                   \(x) weighted.mean(x, WEIGHT, na.rm = TRUE)))
# A tibble: 1 × 2
  TotInc  Wages
   <dbl>  <dbl>

For each of TotInc and Wages: turn the codes into NA, then take the weighted mean.

rate <- 0.01

20000: the function uses rate as it is when the function runs, not when it was written.

total <- 0

Practice: find the bug

We asked an AI: “Show the average 2025 sale price in Vancouver, Burnaby, and Richmond.”

munis <- c("City of Vancouver", "City of Burnaby", "City of Richmond")
for (m in munis) {
  out <- bca |>
    filter(juris_label == m, year(sale_date) == 2025) |>
    summarise(avg = mean(price, na.rm = TRUE))
}
out
# A tibble: 1 × 1
       avg
     <dbl>
1 1053915.

What is wrong? Rewrite it without a loop.

Answer

# The loop overwrites `out`, so it holds only Richmond, the last city,
# and nothing says which city it is. group_by() keeps every city.
bca |>
  filter(juris_label %in% munis, year(sale_date) == 2025) |>
  group_by(juris_label) |>
  summarise(avg = mean(price, na.rm = TRUE))
# A tibble: 3 × 2
  juris_label            avg
  <chr>                <dbl>
1 City of Burnaby   1025556.
2 City of Richmond  1053915.
3 City of Vancouver 1427877.

Practice: explain the placebo code

Simplified from the West Side example. Answer the questions without running it.

placebo <- function(name) {
  data <- sales |>
    mutate(dist = distance_to(name)) |>  # metres from the street
    filter(abs(dist) < 150)
  if (nrow(data) < 100) return(NULL)     # too few sales to estimate
  premium(data)                          # one row: estimate, se, n
}
results <- map(set_names(placebo_streets), placebo) |>
  compact() |>
  bind_rows(.id = "street")
  1. What goes into placebo(), and what comes out?
  2. Which names in the body are not arguments? Where do they come from?
  3. What does map() return? What does compact() do?
  4. Twenty-one streets go in. Why might fewer rows come out?

Answer

  1. A street name goes in. A one-row tibble from premium() comes out, or NULL when fewer than 100 sales are near the street.
  2. sales, distance_to(), and premium(). They are defined earlier in the file. If sales changes before this code runs, the results change.
  3. A named list with one item per street, each a tibble or NULL. compact() removes the NULL items, and bind_rows(.id = "street") stacks the rest with the street names as a column.
  4. Streets with fewer than 100 nearby sales return NULL and drop out. In the example, 18 of 21 streets remain. Check with length(placebo_streets) and nrow(results).

A checklist for reading functions and loops

  1. Inputs and output: what goes into the function, and what comes out (the last line, or return())?
  2. Outside names: which names in the body are not arguments? Where are they set?
  3. Defaults: what does each default choose for you?
  4. Loops and map(): what do they repeat over, and where does each result go?
  5. Counts: how many items go in, and how many come out?
  6. across(): which columns did the selector pick?
